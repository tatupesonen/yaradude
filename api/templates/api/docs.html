API

Everything you can do in yaradude you can do from a script: JSON over HTTPS with a personal API key. A key acts as you, with your role's permissions, and changes made with it are recorded under your name.

Getting started

Base URL
{{ base_url }}/
Format
JSON requests and answers; uploads as multipart/form-data; downloads as files.
Description
OpenAPI 3.1 document for tools (also at {{ base_url }}/openapi.json with a key).
  1. Create an API key on your API keys page. It is shown once; store it like a password.
  2. Put it into the environment, so it never appears in scripts or shell history files: 
    export YARADUDE_API_KEY='yd_…paste your key here…'
  3. Send it in the Authorization header of every request: 
    curl -sS -H "Authorization: Bearer $YARADUDE_API_KEY" {{ base_url }}/me/

Only the header is accepted: the API ignores your browser session and cookies, so a signed-in browser cannot act on it, and API answers never set cookies.

Python

Download yaradude_client.py

The Python examples use yaradude_client.py, a small module that needs only the Python standard library (Python 3.9 or newer, no requests), so it runs on machines without internet access. Download it into the directory of your script; it is preset to {{ server_url }} (override with YARADUDE_URL) and reads the key from YARADUDE_API_KEY.

from yaradude_client import ApiError, call

try:
    page = call("GET", "/rules/", query={"q": "mimikatz"})
except ApiError as error:
    print(error.status, error.error["code"], error.error["message"])

If the server's certificate comes from a private CA (such as the proxy's internal CA), give its certificate to Python with SSL_CERT_FILE=/path/to/ca.pem and to curl with --cacert /path/to/ca.pem. Never turn certificate checks off.

Conventions

Errors

Every error is a JSON object with a stable code and a readable message; invalid fields are listed in fields:

{"error": {"code": "invalid", "message": "The request is not valid.", "fields": {"text": ["This field is required."]}}}
StatusMeaning
400Invalid request (invalid, invalid_json); fields says what to fix.
401No key, or the key is malformed, unknown, revoked or expired, or your account is disabled. Comes with WWW-Authenticate: Bearer.
403Your role does not allow this (permission_denied). Viewers browse, export and scan; Editors also import, create, edit and delete.
404No such object or endpoint.
405Wrong method; Allow lists the right ones.
409Conflict: the rule changed since the version you sent (version_conflict, with current_version), or the rules directory is missing or empty.
413 / 415Body too large / not sent as application/json.
422The rule was refused (rule_rejected: does not parse or compile, or the name is taken; result holds the diagnostic and line) or the scan failed.
429Rate limit reached; wait Retry-After seconds.
500Server error; the details are in the server log, not in the answer.

Pagination

Lists answer one page: {"count", "page", "pages", "page_size", "next", "previous", "results"}. Rules, rulesets and tags come 100 per page, import runs 25, as in the UI. Follow next until it is null; a page number out of range gives the nearest page.

Search, filters and sorting

The list endpoints take the same query parameters as the pages' filter forms and run the same queries, so a URL from the Rules or Rulesets page works with the API path too. A value the UI would ignore (an unknown sort key, for example) is ignored here as well rather than refused. sort takes a key with an optional - for descending.

Edits and deletes

An edit sends the full rule text with the version it is based on; if someone changed the rule meanwhile, nothing is saved and the answer is 409. Deleting is always an explicit DELETE and cannot be undone.

Uploads and downloads

Rule files and scan samples are uploaded as multipart/form-data (curl -F field=@file). They are held in memory only; a sample is never stored or logged. Samples may be up to {{ scan_max|filesizeformat }}, rule files up to {{ rule_file_max|filesizeformat }} each. The API never takes a path on the server. Downloads are answered as files with Content-Disposition; curl -OJ saves them under that name.
